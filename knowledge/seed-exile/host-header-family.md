# Host 头攻击族:特权假设、路由与歧义请求

同一类型漏洞:应用或前置对 HTTP Host 头作了错误假设(特权级、路由目标、
密码重置基址、缓存键),攻击者改写 Host 或构造歧义请求使假设偏移。前置
反向代理的站点表与校验口径是第一道判读面(见 [[front-end-fingerprinting-method]])。

## 子型判型矩阵

| 子型 | 判型特征 | 手法方向 |
|---|---|---|
| 特权假设 | admin 面板按 Host 判特权(如 `localhost`) | 登录态携毒 Host 访面板;匿名常被前置拒,登录态另判 |
| 路由 SSRF | 前端按 Host 路由到任意源站 | 毒 Host 指内网/任意目标,读回响应 |
| 解析差分 SSRF | 前后端 Host 解析口径不一(端口、@、重复头) | 构造前后端各取所需的歧义形 |
| 密码重置毒化 | 重置邮件以请求 Host 为基址 | 毒 Host 使重置链接落自己服务器,读日志取令牌;Host 被边缘钉死时改信 `X-Forwarded-Host`/`Forwarded`,或用端口/引号撑破邮件 HTML 使令牌随受害者后续请求漏出(悬断标记,不必改整段主机) |
| 歧义请求缓存键 | 缓存键取 Host 主机名而路由另取请求分量 | 绝对形请求行 + 毒 Host 使投毒请求落受害者键(与 [[cache-poisoning-family]] 交界) |
| 连接态绕过 | 前端按首个请求的 Host 定连接归属 | 同连接先过合法 Host 再发毒请求 |

## 现代边缘墙(方法位)

毒 Host 直改在现代边缘常全通道封;浏览器臂不可改伪头。判读顺序:先测站点表与
校验口径定可行形(见 [[front-end-fingerprinting-method]]),连接态松弛按题实证
不假设跨题共享。平台实测口径与解锁条件存项目层
[[portswigger-platform-specifics]]。

## 消费者追踪法(先证有人消费,再造形)

注入值无害化的根因常是"没有消费者":改写的值没有任何组件拿去取数。

1. 列出候选消费者:路由器、取数器(SSRF/回调)、缓存键、链接/重定向
   生成器、日志。逐个问"这个组件会对我控制的值做什么"。
2. 每个消费者的证据义务:找到它能被该值驱动的直接证据(行为差分),
   无证据的消费者从计划里划掉。
3. 有消费者再造形:形服务于消费者的解析口径(见
   [[front-end-fingerprinting-method]]),而不是反过来试形碰运气。

## 键域/路由域分离的歧义形枚举清单

缓存键与路由各读请求的不同分量时,投毒=造"键说受害者、路由说载荷源"
的请求。逐轴枚举两侧各读什么:

- 请求行(相对/绝对形)、Host 头(名/值/重复序/端口段)、:authority 伪头、
  大小写与空白变体、连接级状态(首请求的归属)。
- 每轴记两列:键读它吗/路由读它吗;分叉轴=可造分离形的轴。
- 造形后先证"键确实落在受害者域"(命中侧信道),再投载荷。

## 手法序

1. 先测站点表与校验口径(端口自由形、@形、后缀路由、重复头),定可行形。
2. 匿名被拒时先登录再携毒 Host 重试(特权假设题的常见放行差)。
3. 解析差分题找"前端取 A、后端取 B"的形:绝对形请求行、端口注垃圾、
   重复 Host 顺序差。
4. 缓存键题先实测键构成与隔离域(哪些分量进键、路由到他站的响应落谁的
   缓存),再构造"路由到 A、落键在 B"的歧义请求。

关联: [[front-end-fingerprinting-method]]、[[cache-poisoning-family]]、[[hunter-surface-to-hypothesis]]

## 路由与缓存消费者(grok 先例线)

- 路由型 SSRF 第一步是先证「这个 Host 真被拿去连」(OOB 回调),再扫 `192.168.0.0/24`;顺序反了会把「拒绝」误判成「不通」。
- 缓存键分叉的第二 Host 消费者:重复 Host 的第二个值被写进脚本绝对 URL 时,第一个 Host 仍是缓存键——证据是 `X-Cache` miss 变 hit 且受害者键上出现攻击者脚本源;绝对形式请求行是另一种同构分叉。
- 连接态绕过(首条合法后连接放行毒 Host):关键变量是**边缘墙要求的 lab 会话 cookie**(带上后,同 TCP 连接先合法 Host 紧接毒 Host 即放行;实测破此前「rustls 指纹不过边缘」的悲观判);Burp 形是单连接顺序发组。
